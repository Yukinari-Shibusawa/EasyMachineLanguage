# 開発ガイド

## プロジェクト構成

- `include/EasyMachineLanguage.hpp` — AST、プログラムAPI、`ProgramHost`インターフェース
- `src/Program.cpp` — 字句処理、ブロック解析、検証、実行
- `tests/ProgramTests.cpp` — ループ、条件分岐、変数スコープ、エラーのテスト
- `docs/` — 利用ガイドと開発ガイド

EasyMachineLanguageは独立したC++17/CMakeプロジェクトです。ベルト、Marlin、装置通信などの
アプリケーション固有処理を含めず、ホストインターフェースを通して利用側へ委ねます。

## APIとホストの責務

利用側は`easyml::ProgramHost`を継承し、次の仮想関数を実装します。

- `validateInstruction` — 変数展開後の命令1行を検証する。実機動作を起こさない。
- `executeInstruction` — 選ばれた命令を実行する。
- `validateIdentifier` — IF条件で使うホスト固有識別子を検証する。
- `resolveIdentifier` — IF実行時に識別子の数値を解決する。
- `cloneForValidation` — 条件分岐検証用にホスト状態を複製する。
- `mergeValidatedBranches` — 真偽両側の検証後状態を元のホストへ統合する。
- `conditionEvaluated` — 条件評価を通知する。既定の実装は何もしない。

`Program::validate()`はIFの両分岐を別々の複製ホストで検証し、結果を
`mergeValidatedBranches()`へ渡します。条件式の値によって、検証されない分岐ができないように
するためです。ホストは用途に応じて、両分岐に共通する安全な状態だけを統合してください。
FORの本体は全反復値について検証されます。

各ノードには入力ソース名と行番号が保持され、ホスト関数が送出した標準例外も該当位置付きの
エラーに包まれます。ホストがすでに同じ位置を付けた例外は重ねて付加しません。

## 検証と実行

推奨される呼び出し順序:

1. `Program::parse()`で入力をASTへ解析する。
2. `Program::validate()`で命令と条件識別子を検証する。
3. 検証用ホストの状態を実行用ホストへ流用せず、必要に応じて別インスタンスを用意する。
4. `Program::execute()`で条件を評価し、実際に選択された命令だけを実行する。

ライブラリは検証後の実行を自動保証しません。ホストの状態や外部条件が変わった場合には、
利用側で再検証する必要があります。実機制御を行うホストでは、検証コールバックから装置を
動かさず、エラーを成功扱いにしないでください。

## ビルドとテスト

```sh
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

テストはホストのモックを使い、実機や外部サービスへ接続しません。カバレッジを保つため、
制御フローの境界値、ネスト、エラー位置、ホスト状態の分岐統合を変更時に確認します。

## 変更時の確認事項

- 構文や制限を変える場合は、パーサ・検証・実行のテストを追加または更新する。
- エラーにはソース位置を含め、入力エラーを黙って無視しない。
- 新しいドメイン機能はライブラリに埋め込まず、`ProgramHost`経由で利用側に実装する。
- 公開APIまたは制限を変えた場合は[利用ガイド](USAGE.md)とREADMEを同期する。
